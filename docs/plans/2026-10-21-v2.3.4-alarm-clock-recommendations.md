# Nudgio v2.3.4 — making it work as a normal alarm clock

**Date:** 21 October 2026
**Status:** Recommendation, not yet approved. `main` is stamped v2.3.2 (`android/version.properties`); no v2.3.3 exists in git, so decide whether 2.3.4 is intentional or should be 2.3.3.
**Goal:** someone who never imports a photo or video should be able to open Nudgio, set "7:00, weekdays" in a few taps, and trust it as their everyday alarm.

## What blocks that today (verified in code)

| Blocker | Where |
|---|---|
| Saving an alarm **requires** an attachment. The editor refuses to save without one. | `src/features/reminders/ReminderEditorScreen.tsx:389,621` (`validationMediaRequired`) |
| The database column is `NOT NULL`: `media_id` has no way to say "none". | `android/.../data/db/entity/ReminderEntity.kt:44` |
| The app speaks in "reminders" and "moments", not "alarms". | `en.ts` copy |

What already works in our favour: the ringing service already plays your chosen **default ringtone** (or the device alarm sound) when media can't be played (`AlarmRingingService.kt:372-402`, `AlarmToneFallback`), snooze/dismiss work without the UI, and the editor already offers Once / Daily / Selected days / Monthly / Yearly / Custom.

## Recommended for 2.3.4, in priority order

### 1. Alarms without an attachment (the headline change) — medium effort
- Make `media_id` nullable: **Room migration 8 → 9** (SQLite can't drop `NOT NULL` in place, so it's a copy-table migration like `Migration5To6`; keep `schemas/9.json`).
- Editor: remove the media-required rule; the attachment row becomes "Add photo, video or sound (optional)". A no-media alarm rings with the default alarm sound from Settings.
- Carry `mediaId?: string` through the bridge types, backups (optional key, old archives still import) and every place that assumes it (about 60 Kotlin references, mostly `MediaReminderModule`, `ReminderMutationService`, `PendingMediaOpen`; JS: Home, Detail, Moment, `InAppDueCard`).
- Moment/Play for a no-media alarm: no media screen. Show title, message and Snooze/Dismiss, nothing else.
- Don't merge `wip/optional-media-and-screen-header-2026-08-15` (DL-074). It's two months stale and rewrites screens that no longer exist. Use it as a reference only.
- This is the **only** item below that touches the database, so ship it alone in its own commit with its own device upgrade test (v2.3.2 → 2.3.4 with existing reminders).

### 2. Make the title optional, defaulting to "Alarm" — small
Opening the editor to just pick a time should be enough. Auto-label "Alarm" (or the time, "7:00 AM alarm") if left blank. I only confirmed the media rule; check whether the title is also required before sizing this.

### 3. Time first in the editor — small
Reorder the form to: **time → repeat → (optional) label, sound, attachment, snooze.** Today it leads with media. Keep the DL-110 "progressive disclosure" pattern so advanced options stay collapsed.

### 4. One-tap repeat presets — small
Add chips **Once · Every day · Weekdays (Mon–Fri) · Weekends** above the existing day picker. They map onto the existing `weekdays` rule type, so there's no native change.

### 5. Say "alarm" in the UI — small (copy only)
Rename user-visible "Reminder(s)" to "Alarm(s)" (tab, FAB, empty states, notifications, onboarding). Keep internal names (`reminders`, `ReminderMoment`) unchanged. The rule: it's an alarm clock first, and attachments are the special feature. Include the website text (`web/index.html`) and Play/GitHub description.

### 6. Alarm-clock home screen — small
- A clear "Next alarm in 7 h 20 min" line (the `NextMomentCard` exists, so check it reads that way for no-media alarms).
- An on/off switch on every alarm row (the native `setReminderEnabled` already exists), so you can disable one alarm without opening it.
- Quick "In 10 min" / "In 30 min" chips on the new-alarm screen for one-off alarms.

### 7. First run without media — small
Onboarding's call to action should be **"Set your first alarm"**, not "import media". Keep the existing test-alarm step (`scheduleTestReminder`) because it's the best trust-builder.

### 8. Ship the security fixes already in flight — no new work
If the backup-hardening branch (SEC-01/02/04) is merged by release time, include it in 2.3.4's notes. `npm audit fix` for the non-breaking dev-tool advisories is also safe to include.

## Explicitly not in 2.3.4
Timers, stopwatch, world clock, bedtime/sleep features, per-alarm ringtone picker, gradual volume ramp, shake/maths-to-dismiss. All are normal for clock apps but add native code or settings, and none is needed to be "a normal alarm". Revisit after 2.3.4 ships. The Flutter migration (ADR-023) continues in parallel and doesn't block this: item 1's schema change is the one the Flutter build will inherit.

## Suggested release checks
1. Fresh install → create "7:00 weekdays" with **no** attachment and **no** title → rings with the default sound; Snooze and Dismiss work with the app swiped away.
2. Upgrade from v2.3.2 with existing media alarms → all still ring, media still plays after Play, backups taken before and after both restore.
3. Export a no-media alarm and restore it on a clean install.
4. `./gradlew test lintDebug`, `npm run verify`, release-manifest check (no `INTERNET`).
